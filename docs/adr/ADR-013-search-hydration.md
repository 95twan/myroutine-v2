# ADR-013. 검색은 ES로 순서를 정하고, 결과 항목은 상품 DB에서 읽는다

- 상태: 승인 (2026-11-01)
- 관련: [로드맵 5-2](../03-roadmap/part5-review-search.md), [ADR-002](ADR-002-module-boundaries.md), FR-SRC-01

## 맥락
- 검색 결과는 상품 목록 카드와 같은 모양(사진·품절 여부 포함)이어야 한다.
- ES 문서는 `product-upserted` 이벤트로 갱신한다. 이 이벤트는 상품 등록·수정·상태 변경·단종에서만 나간다. 썸네일은 이미지 추가·삭제가, 재고는 재고 조정·주문·환불이 바꾸는데 둘 다 이벤트를 내지 않는다.
- 문서에 사진·재고 여부를 넣으려면 이벤트를 늘려야 한다. 이미지가 바뀔 때 상품 `version`을 올려야 하고(external version은 더 큰 버전만 받는다), 재고는 가용 수량이 0을 넘나드는 모든 경로(예약·해제·확정·복구·조정)에서 감지해 발행해야 한다. 재고 경로는 체크아웃의 핫스팟이다.

## 결정
1. ES는 검색 조건에 맞는 상품의 순서(관련도 → `productId`)와 커서만 정한다.
2. 한 페이지의 상품 ID로 `ProductApi.getOnSaleSummaries`를 한 번 불러 항목(이름·가격·카테고리·썸네일·재고 여부·등록 시각)을 채우고 ES 순서대로 놓는다.
3. DB에서 판매 중이 아닌 상품은 뺀다. 한 페이지가 `size`보다 짧거나 비어 있을 수 있고, `nextCursor`는 ES 결과로 정한다.
4. 자동완성은 이름만 돌려주므로 ES만 읽는다.

## 고려한 대안
| 대안 | 기각 이유 |
|---|---|
| 문서에 썸네일·재고 여부를 넣고 이벤트를 늘린다 | 위 맥락의 비용. 재고 핫스팟 경로에 발행이 늘고, 그래도 반영 전 몇 초는 낡은 값이 보인다 |
| 썸네일만 문서에 넣고 품절은 상세에서만 보여 준다 | 이미지 변경에 `version` 증가가 여전히 필요하고, 검색 카드만 목록 카드와 모양이 달라진다 |
| 화면이 결과마다 상품 상세를 부른다 | 요청이 페이지 크기만큼 늘어난다 |

## 결과
- 검색 결과의 이름·가격·사진·재고 여부는 DB와 같다. 이벤트가 늦게 반영되는 동안의 차이는 순서와 검색 대상 여부에만 남는다.
- 검색 요청마다 상품 DB 조회가 1회 늘어난다(ID `IN`, 최대 50개).
- search가 검색 요청 때 product를 동기로 부른다. Stage 3에서 검색 서비스는 상품 서비스의 조회 API에 의존하고, 상품 서비스가 내려가면 검색도 실패한다. ES 장애가 상품 등록을 막지 않는 방향(NFR-AVL-02)은 그대로다.
- 품절 표시를 위해 계획했던 `product.stock-depleted.v1` 이벤트는 필요 없어져 카탈로그에서 뺐다.

## 면접 연결
- "ES와 DB 값이 다르면?" → 순서는 ES, 표시 값은 DB. 값마다 어느 쓰기 경로가 바꾸는지 보고 나눴다.
- "읽기 모델에 모든 필드를 넣지 않은 이유는?" → 이벤트를 내지 않는 쓰기 경로(이미지, 재고)에 발행을 더하는 비용과 핫스팟
