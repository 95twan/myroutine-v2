## 6-1. 리뷰 · 평점 통계 · 좋아요 (M)
**목표**: 구매확정된 품목당 리뷰 1개. 상품별 평점 분포와 좋아요.
**할 일**
1. `review`, `review_like`, `product_review_stat` 마이그레이션
2. 작성 가능 여부는 `OrderApi`로 확인(본인 품목 + CONFIRMED), `order_line_id` unique
3. 통계는 작성·삭제 트랜잭션에서 조건부 UPDATE로 증감, 좋아요는 `(review_id, member_id)` PK + 원자적 증감
4. 30일 이후 수정 불가, 삭제는 soft delete + 통계 반영, 상품 상세에 평점 요약 추가
5. `review-created` 발행(6-5에서 사용)
**완료 확인**
- [ ] 구매확정 전·남의 품목 리뷰 → 거부, 같은 품목 동시 작성 → 1건
- [ ] 서로 다른 회원 좋아요 동시 100건 → 100
**리뷰 때 물어볼 것**: unique 위반을 트랜잭션 안에서 잡으면 왜 안 되나? (As-Is SUP-05)

## 6-2. 상품 검색 · 자동완성 (M)
**목표**: 키워드 검색과 자동완성. 상품 변경이 몇 초 안에 반영된다. ES가 죽어도 검색만 실패한다.
**새로 등장**: Elasticsearch — 검색 전용 저장소. 원본은 Postgres, ES는 이벤트로 갱신하는 **읽기 모델**이다.
**할 일**
1. docker-compose·테스트에 ES, 인덱스 매핑(edge_ngram 자동완성)
2. `product-upserted`, `product-discontinued` consumer → 색인·삭제, 이벤트 version으로 오래된 이벤트 무시
3. `GET /api/search/products`, `GET /api/search/autocomplete`, ES 클라이언트 타임아웃
**완료 확인**
- [ ] 등록 → 검색됨, 단종 → 검색 안 됨, 순서 역전 이벤트 → 최신 유지
- [ ] ES 중단 → 검색 503, 다른 API 정상
**리뷰 때 물어볼 것**: 검색 결과와 DB가 잠시 다를 수 있는데 괜찮은가?

## 6-3. 무중단 재색인 (S)
**목표**: 전체 재색인 중에도 검색이 멈추지 않는다(As-Is SUP-04).
**할 일**: 새 인덱스 생성 → 전체 적재 → 시작 시각 이후 변경분 재적용 → alias 교체 → 이전 인덱스 삭제. `POST /admin/api/search/reindex`
**완료 확인**: 재색인 중 검색 결과 있음, 재색인 도중 수정한 상품이 새 인덱스에 반영됨

## 6-4. 취향 추천 (M)
**목표**: 장바구니·최근 주문으로 취향을 만들고 비슷한 상품을 추천한다.
**새로 등장**: 임베딩(문장을 숫자 벡터로), pgvector 유사도 검색, Spring AI
**할 일**
1. `product_embedding` 마이그레이션(`vector` 확장)
2. `product-upserted` consumer: 본문 해시가 바뀐 경우에만 OpenAI 임베딩 호출
3. 취향 추천 API, Redis 캐시(30분), `order-paid`·`member-withdrawn` → 캐시 무효화
4. OpenAI는 타임아웃·재시도, 테스트는 가짜 서버
**완료 확인**
- [ ] 같은 본문 이벤트 두 번 → 임베딩 호출 1번
- [ ] OpenAI 실패 → 재시도 → DLT, 상품 기능은 정상
**리뷰 때 물어볼 것**: OpenAI 비용을 어떻게 관리했나?

## 6-5. 리뷰 임베딩 · 월간 리뷰 요약 (M)
**목표**: 매월 1일 상품별 리뷰를 LLM으로 요약. 새 리뷰가 없으면 건너뛴다.
**할 일**: `review-created` consumer(리뷰 임베딩), `review_summary` 마이그레이션(`product_id, period_end` unique), 요약 잡(잡 락, 상품별 실패는 건너뛰고 계속)
**완료 확인**: 잡 두 번 → 요약 1건, 새 리뷰 없음 → LLM 호출 0
**리뷰 때 물어볼 것**: 리뷰가 너무 많으면 무엇을 프롬프트에 넣나? (원 프로젝트 면접 질문 1.6)
