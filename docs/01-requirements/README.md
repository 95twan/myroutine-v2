## 0. 제품 개요
판매자가 가게를 열어 상품을 등록하고, 구매자는 여러 가게의 상품을 장바구니에 담아 **한 번에 결제**하거나 **정기 구독**하는 오픈마켓.
결제는 **PG(Toss) 직접결제와 예치금(지갑)을 함께 쓰는 복합결제**를 지원하고, 판매 대금은 구매확정 후 월 단위로 정산되어 판매자 지갑에 입금된다.

### 용어
| 용어 | 정의 |
|---|---|
| 주문(Order) | 구매자의 1회 결제 단위. 여러 가게의 상품을 포함할 수 있음 |
| 가게주문(ShopOrder) | 주문을 가게별로 나눈 처리 단위. 판매자는 이 단위로 발송·상태를 관리 |
| 주문품목(OrderLine) | 가게주문 안의 상품 1종. 취소·환불·리뷰·정산의 최소 단위 |
| 재고 예약(Reservation) | 결제 완료 전 재고를 임시 점유한 상태. 만료 시간이 있음 |
| 예치금(Wallet) | 회원별 잔액. 충전·주문 사용·환불 적립·정산 입금·출금에 사용 |
| 예치금 보류(Hold) | 결제 진행 중인 주문을 위해 잔액 일부를 사용 불가로 묶어둔 상태 |
| 원장(Ledger) | 예치금의 모든 증감 기록. 잔액은 원장 합계와 항상 일치해야 함 |
| 구매확정 | 구매자가 확정하거나 배송완료 후 일정 기간이 지나 자동으로 확정된 상태. 이후 취소·환불 불가, 정산 대상 |
| 회차(Cycle) | 구독의 1회 결제·주문 단위. 회차당 주문은 최대 1건 |
| 빌링키 | 정기결제를 위해 PG에 등록한 카드 자동결제 키 |

## 1. 액터
| 액터 | 설명 |

## 4. 비즈니스 규칙 · 정합성 불변식
v2의 핵심 품질 목표. 모든 불변식은 **자동화 테스트로 검증**한다(NFR-TST).

| ID | 불변식 |
|---|---|
| INV-01 | 주문 결제 총액 = Σ품목 금액(서버 확정가 × 수량) = PG 승인 금액 + 예치금 사용 금액 |
| INV-02 | PG 승인 1건은 정확히 1개 주문(또는 충전 1건)에 1회만 반영된다. 반영되지 못한 승인은 반드시 취소된다 |
| INV-03 | 재고는 음수가 될 수 없고, `가용 + 예약중 + 확정판매 = 입고 누계`가 항상 성립한다 (환불 복구는 확정판매 → 가용) |
| INV-04 | 만료되거나 해제된 예약의 재고는 반드시 가용재고로 돌아온다 |
| INV-05 | 예치금 잔액 = 원장 합계 ≥ 0, 가용잔액 = 잔액 - 보류액 ≥ 0 |
| INV-06 | 품목별 누적 환불액 ≤ 품목 결제액, 주문별 PG 누적 취소액 ≤ PG 승인액 |
| INV-07 | 구매확정 품목은 정확히 1회 정산된다. 정산되지 않은 구매확정 품목이 남지 않는다 |
| INV-08 | 구독 1개의 회차 1개에 대해 결제 완료(PAID) 주문은 최대 1건이다 (실패한 시도의 주문은 결제실패로 남음) |
| INV-09 | 회원의 SELLER 권한 보유 여부 = 등록 완료되고 삭제되지 않은 가게가 1개 이상 있는지 여부 (최종적 일관성) |
| INV-10 | 서비스 간 이벤트는 최소 1회 전달되고(at-least-once), 모든 소비자는 같은 이벤트를 여러 번 받아도 결과가 같다 |

## 6. 핵심 사용자 시나리오 (요약)
상세 시퀀스와 상태머신은 Phase 2에서 설계한다.

**S1. 복합결제 주문**: 장바구니(가게 A 2개, B 1개) → 주문서(예치금 5,000원 사용) → 서버 가격 확정, 재고 예약(15분), 예치금 5,000원 보류 → Toss 결제창(나머지 금액) → 승인 → 주문 결제완료, 가게주문 A·B 생성, 예약·보류 확정 → 판매자 A·B에게 알림

**S2. 결제 중 이탈**: 주문서 생성 후 결제창을 닫음 → 15분 후 예약 만료 → 재고 복구, 예치금 보류 해제, 주문 만료 처리

**S3. 결제 결과 불확실**: 승인 요청(주문 PAYMENT_IN_PROGRESS) 중 PG 타임아웃 → 결제 UNKNOWN, 주문은 만료 대상에서 제외 → 대사 잡이 PG 조회 → 승인이면 주문 완료, 미승인이면 주문 실패 처리. 승인됐는데 주문을 완료할 수 없으면 PG 취소(보상) + 알림

**S4. 품목 취소**: 가게 A 품목 1개만 취소(발송 전) → 품목 금액 계산 → PG 부분취소(POL-08) → 재고 복구 → 다른 품목은 그대로 진행

**S5. 구독 회차**: 매주 월요일 회차 → 시스템이 주문 생성(회차 키로 중복 방지) → 빌링키 결제 → 실패하면 다음 날 재시도, 3회 실패 시 일시정지

**S6. 정산**: 매월 5일 → 전월 구매확정 품목을 가게별로 집계 → 수수료 차감 → 판매자 예치금 입금 → 재실행해도 중복 없음

**S7. 가게 삭제**: 마지막 가게 삭제 요청 → 진행 중 주문·구독 확인 → SELLER 회수 Saga → 상품 단종·구독 종료 이벤트
